# RiseLight native shell (Capacitor)

Capacitor wraps the **same** static Nuxt build (`.output/public`) in native iOS
and Android apps — no rewrite, no separate codebase. The point is to unlock what
a PWA fundamentally can't do:

- **Background / locked-screen audio** — play white noise, rain, etc. all night
  with the screen dark (a PWA's AudioContext is suspended when backgrounded).
- **Local notification alarms** when the app is closed (a follow-up — see below).
- **App Store / Play Store presence.**

The web app stays exactly as-is and keeps deploying to Netlify as a PWA; the
native apps are an additional target that reuses 100% of it.

## What's already scaffolded

- `capacitor.config.ts` — `webDir: '.output/public'`, appId `com.riselight.app`.
- `ios/` and `android/` native projects (generated by `npx cap add`).
- **iOS background audio is wired**: `UIBackgroundModes: [audio]` in
  `ios/App/App/Info.plist` and an `AVAudioSession(.playback)` set at launch in
  `ios/App/App/AppDelegate.swift`. This is what keeps the Web Audio sounds
  playing when the screen locks.
- npm scripts: `build:native`, `cap:sync`, `cap:ios`, `cap:android`.

## One-time local setup (not present in this environment)

- **iOS**: full **Xcode** (not just Command Line Tools) —
  `sudo xcode-select --switch /Applications/Xcode.app`; then **CocoaPods**
  (`sudo gem install cocoapods`) and run `pod install` in `ios/App` (Capacitor
  runs it automatically on `cap sync` once CocoaPods is present).
- **Android**: **Android Studio** + SDK + a JDK.

## Build & run

```bash
npm run build:native      # nuxt generate  →  cap sync (copies web build into both platforms)
npx cap open ios          # open in Xcode  → pick a team under Signing, run
npx cap open android      # open in Android Studio → run
```

`cap:ios` / `cap:android` scripts do sync + open in one step. Re-run
`npm run build:native` (or `npm run cap:sync`) after any web change.

## Verifying background audio (the key win)

1. Build to a **real device** (background audio behaves differently in the
   simulator).
2. Start a sound in the app, then lock the screen. It should keep playing.
3. If it stops, confirm the Info.plist background mode and the AppDelegate audio
   session are intact after a `cap sync` (sync doesn't overwrite native source,
   but re-check after Capacitor upgrades).

## Next steps (not yet implemented)

- **Alarm when the app is closed**: add `@capacitor/local-notifications`,
  schedule a notification at the wake time so the alarm fires even if the app
  isn't foregrounded. Pair with the existing schedule in `useNightLight`.
- **Keep-awake**: the web `useWakeLock` covers foreground; consider
  `@capacitor-community/keep-awake` for parity in the native shell.
- **Store assets**: app icons/splash via `@capacitor/assets`; set version and
  signing in each platform project.

## Notes

- The service worker and `localStorage` both work inside the WKWebView / Android
  WebView, so settings persistence and offline behavior carry over unchanged.
- Because the app is served from the app bundle, the native builds don't depend
  on Netlify at all.
